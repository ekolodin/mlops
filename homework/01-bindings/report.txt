Контракт функции tensor_ops.mac(a, b, c)
- Возвращает out[i, j, k] = a[i, j, k] * b[i, j, k] + c[i, j, k]. Умножение поэлементное, не матричное; broadcasting запрещён.
- Входы: три numpy.ndarray с dtype native-endian float64, 3 оси, одинаковые формы.
- Память: входы должны быть C_CONTIGUOUS и ALIGNED; read-only входы допустимы.
- Выход: новый C-contiguous массив float64 той же формы с собственным буфером. Входы не изменяются, память с ними не разделяется.
- Пустые массивы (нулевая ось) допустимы: возвращается пустой массив той же формы, ядро к указателям не обращается. Проверки dtype, формы и layout для пустых входов тоже выполняются.
- Ошибки: список, скаляр, неверный dtype или порядок байтов -> TypeError (неявного преобразования нет, у всех аргументов py::arg(...).noconvert()). Неверная форма, ndim или layout (не C-contiguous, не aligned) -> ValueError без падения интерпретатора.
- Вычисление выполняется только в C++-ядре mac_kernel (cpp/kernel.cpp) одним плоским циклом по N элементам. Валидация, выделение результата и экспорт находятся в cpp/bindings.cpp.

Build и runtime dependencies
- Build: scikit-build-core==1.0.3, pybind11==3.1.0, cmake==4.4.3, ninja==1.13.2, компилятор C++17 (MSVC).
- Runtime: numpy==2.5.3. Устанавливается автоматически при pip install wheel, что подтверждается его установкой в чистом env (Task #4): numpy 2.5.3 есть в pip list, хотя вручную не ставился.
- pytest: нужен только проверяющему и в зависимости пакета не входит.
- В env получателя нет build, scikit-build-core, pybind11, cmake и ninja; компилятор для установки готового wheel не нужен.

Ограничения реализации
- Поддерживаются только C-contiguous выровненные массивы float64 с native-endian порядком байтов; остальные входы отклоняются, а не преобразуются. Для подготовки входа можно явно вызвать np.require(x, dtype=np.float64, requirements=["C", "A"]).
- Только 3D-массивы одинаковой формы, без broadcasting.
- Без многопоточности и SIMD-оптимизаций, GIL не освобождается, т.к. ускорение относительно NumPy не являлось целью.
- Поведение на NaN/inf и при переполнении специально не проверялось.
- Wheel собран и проверен только для CPython 3.13, Windows x86_64 (cp313-cp313-win_amd64); для других ОС и версий Python его нужно собирать заново.

Task #5
Собственные тесты и проверка их эффективности

В папку student_tests добавлено 7 тестов, покрывающих численные, негативные и граничные сценарии. Все они вызывают установленный wheel-пакет tensor_ops и проверяют результат независимо от реализации.

Описание пойманной ошибки:
Я внес дефект в реализацию C++ ядра (cpp/kernel.cpp), удалив слагаемое c[i] из формулы (строка стала: out[i] = a[i] * b[i];). После пересборки пакета и запуска python -m pytest tests student_tests -q тест test_known_values_on_nontrivial_shape успешно упал с AssertionError, показав расхождение между ожидаемым массивом и полученным результатом, что подтвердило работоспособность теста.

После возврата правильной формулы (out[i] = a[i] * b[i] + c[i];) и повторной сборки все 47 тестов (включая 7 собственных) успешно прошли.

Были добавлены тесты по следующим сценариям:

Численный: test_known_values_on_nontrivial_shape: проверка точных значений на массивах формы (1, 3, 2).

Негативные: test_fortran_layout_is_rejected, test_transposed_view_is_rejected, test_scalar_and_zero_dim_array_are_rejected: проверка отклонения неверных layout-ов, типов и размерностей с ожидаемыми исключениями (ValueError/TypeError).

Память и границы: test_same_object_for_all_inputs (проверка отсутствия пересечения памяти между входом и выходом, а также неизменности входа), test_empty_inputs_with_wrong_dtype_are_still_rejected, test_empty_inputs_with_mismatched_shapes_are_rejected (проверка валидирования пустых массивов).
